# يوسف للعطور

نظام إدارة محل ونقطة بيع (POS) **لمحل عطور**، يعمل بالكامل في المتصفح — واجهة أمامية فقط، بلا خادم ولا قاعدة بيانات ولا خطوة بناء.

- **المجال:** عطور رجالية ونسائية ومشتركة، عطور شرقية وعود، بخور ودهن عود ومسك، عطور شعر، بودي سبراي ومزيلات، معطرات جو وسيارة، أطقم وهدايا، عبوات تقطيع (ديكانت).
- **القاعدة الجوهرية:** **كل حجم من العطر صنف مستقل** — له باركوده الخاص وتكلفته وسعره ورصيده وحدّ التنبيه الخاص به. «سوفاج 100 مل» و«سوفاج 60 مل» سجلّان منفصلان تمامًا.
- **طرق الدفع ثلاث فقط:** نقدي · بطاقة · دين. لكل واحدة أثر مختلف على **الصندوق** والمخزون والربح والذمم (الجدول أدناه).
- **اللغة والاتجاه:** العربية، RTL بالكامل.
- **التقنيات:** HTML + CSS + JavaScript خالص، بدون أي مكتبات خارجية.
- **البيانات:** تجريبية مولَّدة محليًا بمولّد أرقام عشوائية مُزرَع (seeded) — نفس البيانات في كل تشغيل ما لم تُعد توليدها. تُحفظ في `localStorage`.
- **العملة والسياق:** دينار ليبي (د.ل) بثلاث خانات عشرية، أسماء ومدن ليبية، تنسيق `ar-LY`.

## التشغيل

**مباشرة:** افتح `index.html` بنقر مزدوج. كل شيء يعمل عبر `file://` (لا وحدات ES، لا CORS، لا خادم ولا API).

**خادم محلي (اختياري):**

```bash
cd hesham-store
python3 -m http.server 8080
# ثم افتح http://localhost:8080
```

**النشر:** ارفع المجلد كما هو إلى GitHub Pages أو Netlify أو أي استضافة ملفات ثابتة.

## النشر على GitHub Pages

المشروع ملفات ثابتة بالكامل، فأبسط نشر هو رفع المجلد كما هو:

```bash
cd youssef-perfumes-store
git init -b main
git add .
git commit -m "يوسف للعطور — نظام إدارة المبيعات والمخزون والصندوق"
git remote add origin https://github.com/USERNAME/youssef-perfumes-store.git
git push -u origin main
```

ثم من **Settings ← Pages** اختر المصدر `Deploy from a branch`، والفرع `main` والمجلد `/ (root)`. بعد دقيقة يصبح الموقع على:

```
https://USERNAME.github.io/youssef-perfumes-store/
```

- ملف `.nojekyll` يمنع GitHub Pages من معالجة الملفات بـ Jekyll، فلا يُتجاهل شيء.
- **لا ترفع** `node_modules/` — هو مستثنى في `.gitignore`، ويُعاد بناؤه بأمر `npm install` (والأدوات في `tools/` للتطوير فقط ولا يحتاجها الموقع المنشور).
- التطبيق لا يستخدم أي مسار مطلق ولا يتصل بأي خادم أو API، فيعمل من أي مجلد فرعي بلا تعديل.
- الطلب الخارجي الوحيد اختياري: ورقة أنماط خط **IBM Plex Sans Arabic** من Google Fonts (ثلاثة أسطر في `<head>`)، تُحمَّل بلا حجب للرسم ومع بديل نظامي آمن. احذفها فيصير المشروع معزولًا عن الشبكة تمامًا.

## نموذج الصندوق (أهم جزء في النظام)

الصندوق هو **نقد الدرج فعلًا**، ويُحسب من سجل أحداث لا من حقول متراكمة، فلا يخطئ مع التعديل والإلغاء:

| العملية | المخزون | الربح | الصندوق | ذمة العميل |
|---|---|---|---|---|
| بيع نقدي | ينزل | يُسجَّل | **يدخل كامل المبلغ** | — |
| بيع بالبطاقة | ينزل | يُسجَّل | **لا يدخل إطلاقًا** | — |
| بيع بالدين | ينزل | يُسجَّل | لا يدخل | تُسجَّل |
| دفعة أولى وقت بيع الدين | — | — | يدخل مقدار الدفعة فقط | الباقي |
| تحصيل دين (نقدًا) | — | — | **يدخل** | تنقص |
| تحصيل دين (بطاقة) | — | — | لا يدخل | تنقص |
| دين يدوي على عميل | — | — | لا يلمس الصندوق | تزيد |
| مصروف نقدي | — | — | **يخرج** | — |
| مصروف بالبطاقة | — | — | لا يلمس الصندوق | — |
| إرجاع فاتورة نقدية | **يعود** | يُلغى | يخرج (استرداد) | — |

**المعادلة الثابتة** (تُختبر آليًا بعد كل عملية):

```
الرصيد المتوقع = مُرحَّل + مبيعات نقدية محصَّلة + دفعات أولى + تحصيل ديون نقدية + إيداعات أخرى
               − استردادات − مصروفات نقدية − سحوبات أخرى
```

الربح **شيء** والمحصَّل فعليًا **شيء آخر**: فاتورة دين بـ 920 د.ل تُحتسب ربحًا يوم بيعها، ولا يدخل الصندوق منها شيء حتى تُحصَّل.

### دوال المفتاح في `store.js`

```js
HS.store.label(p)              // "سوفاج EDT · 100 مل" — الاسم مع الحجم في كل الشاشات
HS.store.byBarcode(code)       // حلّ الصنف من باركوده (للماسح ونقطة البيع)
HS.store.barcodeTaken(code, id)// منع تكرار الباركود
HS.store.saleProfit(sale)      // Σ الكمية × (السعر − التكلفة) − الخصم
HS.store.cash(range)           // الصندوق: مقبوضات، مدفوعات، متوقع، وخارج الصندوق
HS.store.debts(range)          // الديون: ممنوح، محصَّل، متبقٍ، حالات، مدينون
HS.store.addDebt(id, amount)   // دين يدوي — مع تراجع
HS.store.customerPayment(...)  // تحصيل جزئي أو تسوية، بتاريخ قابل للترجيع
```

كل عملية تحرّك مالًا تُصدر الحدث `cash:change`، فتتحدّث لوحة التحكم وصفحة الصندوق والتقارير فورًا.

### عقد البرمجة

```js
HS.pages.dashboard = function (root, ctx) { … };  // صفحة (أو كائن فيه render)
HS.action("prod-new", function (btn, ev) { … });  // تفويض نقر عبر data-action
HS.bus.on("sale:created", fn);                    // أحداث الحالة
HS.ui.modal({ title, body, footer, onMount });    // نافذة
```

- **لا وحدات ES** — وسوم `<script>` تقليدية بترتيب ثابت، لأنها الطريقة الوحيدة التي تعمل عبر `file://`.
- **لا خادم ولا API** — لا `fetch` ولا `XMLHttpRequest` ولا WebSocket في كل الكود؛ البيانات كلها في `localStorage`.
- **طلب خارجي واحد اختياري** — خط IBM Plex Sans Arabic من Google Fonts، محمَّل بـ `media="print"` ثم `onload` فلا يحجب الرسم، و`--font-ui` ينتقل تلقائيًا إلى Noto Sans Arabic ← Segoe UI ← Tahoma ← خط النظام إن تعذّر. احذف الأسطر الثلاثة من `<head>` ليعمل المشروع بلا شبكة إطلاقًا. الأيقونات كلها SVG مضمّنة.
- **`localStorage` داخل `try/catch`** — يعمل التطبيق حتى مع تعطيل التخزين.
- **خصائص CSS المنطقية فقط** (`margin-inline`, `inset-block-start`) احترامًا لـ RTL.
- **لا `transition: all`**، و`body[data-motion="off"]` يلغي الحركة.
- **كل الطوابع الزمنية** بالساعة والدقيقة والثانية، فتعمل مخططات الساعات وأوقات الإيصالات بواقعية.

## الفحص

```bash
npm install                # يثبّت jsdom (للفحص فقط — التطبيق لا يحتاجه)
npm test                   # يشغّل الفحوص الأربعة بالترتيب

# أو كل فحص على حدة:
npm run test:smoke         # 14 مسارًا + 12 سيناريو حالة     → 0 أخطاء 0 تحذيرات
npm run test:ui            # 52 فحص نقر حقيقي                → 52/52
npm run test:cash          # ثوابت الصندوق والديون والأرباح   → 0 أخطاء
npm run test:spec          # قبول مواصفات محل العطور          → كلها ناجحة
```

إن لم يكن `jsdom` مثبتًا تطبع الأدوات رسالة واضحة وتتوقف بدل أن تنهار بمسار غامض.

`spec.js` هو اختبار المتطلبات: يتحقق أن كل حجم سجل مستقل، وأن الباركود المكرر مرفوض مع ذكر الصنف الذي يملكه، ويسير على طرق الدفع الثلاث واحدة واحدة فيقيس أثرها على الصندوق والمخزون والربح والذمة، ثم يحصّل دينًا جزئيًا وكاملًا، ويضيف دينًا يدويًا ويسدده، ويسجّل مصروفًا نقديًا وآخر بالبطاقة، ويرجع فاتورة نقدية، ويعيد فحص معادلة الصندوق بعد **كل** خطوة، وأخيرًا يمرّ على الشاشات ويتأكد من ظهور الحقول المطلوبة فيها.

## ملاحظات

- البيانات **تجريبية بالكامل** لأغراض العرض؛ لا خادم ولا مصادقة حقيقية.
